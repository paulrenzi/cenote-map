# Riviera Maya Cenote Map

A fast, free, independent trip planner for the cenotes of the Yucatán Peninsula — Cancún and the Riviera Maya, plus day-trip-distance cenotes in Valladolid, Chichén Itzá, and Mérida / Homún / Cuzamá.

**Live:** https://paulrenzi.github.io/cenote-map/

**69 cenotes**, each with a verified unique photo, bilingual EN/ES, with activity-correct filtering (swim vs. snorkel vs. cavern dive vs. cave dive), distance from where you're actually staying, current prices and hours, and kid-friendly flags.

Built as an honest alternative to TripAdvisor's cenote listings.

## Stack
- Static site: vanilla HTML/CSS/JS, no framework
- Map: [MapLibre GL JS](https://maplibre.org) via CDN, lazy-loaded on scroll (IntersectionObserver)
- Tiles: [OpenFreeMap](https://openfreemap.org) Positron — free, no API key
- Fonts: Fraunces + Manrope via Google Fonts (preconnected)
- PWA: service worker, network-first for the app shell, cache-first for images
- i18n: EN + ES, swap via `?lang=` query param + `data-i18n` attributes
- SEO: per-cenote detail pages, JSON-LD `TouristAttraction` schema, sitemap, hreflang
- Hosting: GitHub Pages
- Backend (optional): Cloudflare Worker + D1 + Turnstile for live conditions reports

Free-tier everything. No analytics, no trackers, no ads.

## Data model

Each cenote in `data/cenotes.json` has bilingual `name_en`/`name_es` + `blurb_en`/`blurb_es`, `coords: [lat, lng]`, `activities` array (`swim`, `snorkel`, `cavern_dive`, `cave_dive`, `cliff_jump`, `zip_line`, `rappel`), `skill_min`, `kid_friendly`, `hours`, `cost_mxn`, `access`, `amenities`, `ownership`, `eco` notes, and a `verified` date that drives a freshness badge in the UI.

See the `_schema_notes` block at the top of the file for field details.

## Adding a cenote
1. Edit `data/cenotes.json` — copy the nearest existing record as a template, give it a unique kebab-case `slug`.
2. Set `verified` to today's date.
3. Fetch a photo: `python fetch-photos.py` (pulls from Wikimedia Commons, license-filtered) — OR drop a manually-sourced WebP into `images/cenotes/<slug>.webp` and add an entry to `data/photos.json` with credit + license + source URL.
4. Regenerate detail pages: `python generate-pages.py`.
5. Bump the cache version (see Cache discipline below) if you also touched any shell file.
6. Commit + push. GitHub Pages auto-deploys on push to `main`.

## Photo pipeline

Photos come from three sources, in priority order:
1. **Wikimedia Commons** (CC BY / CC BY-SA / public domain) — pulled by `fetch-photos.py` with geo-search and category-search; license-filtered; landscape preferred.
2. **Explicit Wikimedia override** in `data/photo_overrides.json` when the auto-fetch picks the wrong file.
3. **Publisher `og:image`** scraped from a *dedicated* cenote page (resorts, tour operators, Mexico-travel blogs) — never from a listicle hero. Credited to the publisher with a link to the source article.

License + credit for every photo is tracked in `data/photos.json` and surfaced in `ATTRIBUTIONS.md` (regenerated whenever photos change).

### Verification discipline

Two failure modes have to be defended against, both of which silently bypass an HTTP-200 check:

- **Listicle-hero misattribution.** A travel article titled "Top 30 Cenotes" carries one `og:image` (the article's hero) that gets attached to every cenote mentioned in the article. The hero is of *one* cenote, not all of them. Defense: after every batch download, hash-dedupe across the whole site. Any image bytes that appear under more than one slug are rejected for all of them.
- **Wikimedia name collision.** The Commons search API matched "kikil" to an Indonesian soup, "cascabel" to a 1730s cannon breech, and "atik" to a star — all real CC-licensed files. Defense: require the file title to contain the substring `cenote` AND a slug-specific keyword (with explicit aliases for cenotes known by two names, e.g. xkeken ↔ dzitnup).

If a publisher objects to use of an og:image, swap it in `data/photos.json` and re-run the build — the change is a one-line edit.

## Cache discipline

The service worker (`sw.js`) is network-first for shell files (HTML/JS/CSS/JSON/manifest) and cache-first for images. **Any change to a shell file requires bumping the version in three places:**

1. `CACHE` const in `sw.js` (e.g. `cenote-map-v7` → `v8`)
2. `?v=N` query strings in `index.html` on every shell asset link
3. `?v=N` query strings on the manifest link

The version bump invalidates the browser's HTTP cache AND the service worker cache simultaneously. Without this, returning visitors will see stale assets for days.

Photos under `images/cenotes/` don't need a version bump — the slug-based filename is stable and the SW serves them cache-first.

## Running locally
Any static server works:
```
python -m http.server 8000
```
Then open http://localhost:8000.

## Conditions backend (optional)

The `worker/` directory holds a Cloudflare Worker + D1 backend for live "how was it today" reports (crowd level, visibility, water clarity, notes). The frontend degrades gracefully if it isn't deployed — the Report button just doesn't render.

To turn it on:
1. Follow `worker/README.md` to deploy and get the workers.dev URL.
2. Create a Turnstile site at dash.cloudflare.com → Turnstile (free).
3. In `app.js`, fill in:
   ```js
   const CONFIG = {
     API_BASE: "https://cenote-conditions.<acct>.workers.dev",
     TURNSTILE_SITE_KEY: "0x4AAA..."
   };
   ```
4. Commit — GitHub Pages picks it up on push.
